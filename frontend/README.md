## 작성 규칙

- 화면마다 진입 경로, 구성 요소, 상태, 버튼·동작 표를 쓴다.
- 버튼 번호(①②③…)는 PPT 화면의 번호 표시와 같다.
- 화면별 백엔드 요소는 UI 확정 후 단계 3에서 적는다.

## 공통 요소

- 하단 탭 바: 홈 / 굿즈 탐색 / 내 방 / 매장 찾기 / 마이
- 상품 카드: 상품 이미지, IP·캐릭터, 상품명, 온라인 배지, 오프라인 배지, 찜(♡)
- 톤: UI 시안 표지(로그인 화면)에 맞춘다 — 남색(`#13294B`, 로고 · 주요 버튼 · 선택 상태), 민트(`#22C7A0`, 진행 · 강조), 피치(`#FFB896`, 알림 점), 베이지 카드 테두리. 재고 · 판매 경로 색(파랑 · 초록 · 노랑 · 빨강)은 뜻이 있는 색이라 그대로 (`lib/core/theme/app_colors.dart`)
- 표지 그림(로고 · 가챠 · 쿠지 · 이타백 · 키링 · 곰 스탠드 · 포토카드)은 표지 이미지에서 잘라 배경을 투명하게 한 것 (`assets/brand/`)

|온라인 배지|오프라인 배지|
|--|--|
|`온라인 4곳 · 최저 12,900원` (배송비 포함 총액)|`근처 2곳 재고`|

> 판매 경로가 없는 쪽 배지는 표시하지 않는다.

### 1. 홈

- 진입 경로: 앱 실행, 하단 탭 [홈]
- 구성 요소 (위에서 아래 순서)
  1. 상단 바: 굿모닝 로고, 알림 🔔
  2. 검색창: 텍스트 입력, 사진 검색 📷
  3. 판매 경로 필터: 전체 / 🌐 온라인 / 📍 오프라인
  4. 내 IP: 회원가입 때 고른 IP (캐릭터 사진 타일), 맨 끝에 [+ 추가]
  5. 내 주변 재고: 가까운 매장 2~3곳 카드 (매장 이름, 거리, 내 IP 굿즈 재고 수)
  6. 내 IP 신상품: 상품 카드 목록
  7. 하단 탭 바 (🏠 홈 / 🧸 굿즈 탐색 / 📍 매장 찾기 / 🙂 마이)
- 상태
  - 로딩: 각 영역 자리에 회색 상자 표시
  - 위치 권한 없음: 내 주변 재고 자리에 [위치 허용] / [지역 선택] 버튼
  - 오프라인 필터 선택 시: 내 주변 재고 영역을 맨 위로 올림

|번호|버튼·동작|결과|
|--|--|--|
|①|알림 🔔|알림 목록 (가격 하락, 재입고, 제보 처리 결과)|
|②|검색창에 입력 후 검색|검색 결과 화면으로 이동|
|③|사진 📷|사진 촬영·선택 → 사진 검색 결과 화면으로 이동|
|④|판매 경로 필터|홈의 상품·매장 목록을 선택한 경로 기준으로 바꿈|
|⑤|내 IP 타일 · [전체] · [+ 추가]|해당 IP 화면 / 굿즈 탐색 탭 / IP 목록 조정 화면|
|⑥|내 주변 매장 카드 · [지도]|매장 상세 / 매장 찾기 (지도 뷰)|
|⑦|상품 카드 · ♡|상품 상세 / 찜 추가·해제|
|⑧|하단 탭|홈 / 굿즈 탐색 / 내 방 / 매장 찾기 / 마이|

### 2. 굿즈 탐색

- 진입 경로: 하단 탭 [굿즈 탐색], 홈의 내 IP [전체]
- 구성 요소: 상단 제목, 검색창 (IP·캐릭터 이름과 별칭), 판매 경로 필터, 품목으로 보기, 내 IP 타일 (3열), [IP 목록 조정]
- 내 IP에는 회원가입 때 고른 IP만 보인다. IP 추가 요청은 IP 목록 조정 화면 안에 있다.

|번호|버튼·동작|결과|
|--|--|--|
|①|검색창|IP · 캐릭터 이름과 별칭으로 찾기 (먼작귀 → 치이카와)|
|②|판매 경로 필터|홈과 같은 필터|
|③|품목으로 보기|피규어 · 인형 · 키링 · 아크릴 · 프라모델 · 랜덤 목록으로 이동|
|④|내 IP 타일|IP 화면으로 이동 (캐릭터 선택 · 품목 필터)|
|⑤|IP 목록 조정|보일 IP 고르기 · 빼기, 없는 IP는 추가 요청|

### 로그인 (표지)

- 구성: 굿즈 스티커 줄 · 로고 · "촬영 → 키링" 그림 · `SNS로 모으러 가기` · 카카오 / 네이버 / 구글 / Apple · 로그인 없이 모아보기
- SNS 버튼은 프로토타입이라 실제 로그인 없이 IP 고르기(6)로 간다. 이메일 로그인 칸은 표지에 없어서 뺐다 (이메일 회원가입 화면 `/signup`은 코드에 남아 있다)

### 내 방 (하단 탭, 신규)

UI 시안(`시안.html`)의 흐름을 실제 촬영 영상과 3D 복원 결과로 보여 준다. 결과물은 `backend/ai/asset3d/`가 만든다 (`assets/room/<id>/`).

|단계|화면|쓰는 결과|
|--|--|--|
|360° 촬영|[촬영 영상 재생] → 진행률 · 각도|실제 영상에서 고른 프레임 36장|
|윤곽 분리|촬영이 끝나면 이어서 재생|같은 프레임에 SAM 3가 자른 굿즈 영역(민트 윤곽)|
|3D 복원|좌우로 끌면 회전 (손대기 전에는 천천히 돈다). [가우시안 스플래팅 (영상)] · [SAM 3D (사진 1장)]을 바꿔 같은 각도에서 비교, 방법마다 쓴 사진 수 · 가우시안 수 · 확인용 PSNR 또는 걸린 시간 · 주의점|두 방법의 결과를 같은 카메라로 5°씩 돌려 렌더링한 72장씩|
|내 방 꾸미기|놓을 에셋의 3D 방법 고르기, 벽지 · 바닥 · 선반 색, 트레이의 굿즈를 칸(선반 위 · 선반 아래 · 테이블 · 바닥)에 끌어 놓기 또는 누르기, 놓은 굿즈를 좌우로 끌면 회전, 누르면 상품 정보|시안의 방 그림 · 칸 위치 · 색|

- [내 방 바로 열기]: 앞 단계를 건너뛰고 방으로. [처음으로]: 다시 촬영부터
- [내 굿즈 직접 촬영하기] → 자동 촬영 가이드(`/capture`): 카메라 + 기울기 센서. 굿즈를 받침 위에 두고 둘레를 돌면, 높이 3줄(낮게 · 중간 · 높게) × 방향 24칸 중 아직 안 찍은 칸에서 멈출 때 자동으로 찍는다(얼굴 등록처럼 둘레 눈금이 민트로 채워짐). 흔들리면 기다린다. [사진 받기]로 사진 + 각도(zip)를 내려받아 `backend/ai/asset3d`에 넣는다. 아이폰 사파리는 [촬영 시작]을 누를 때 기울기 센서 허락을 묻는다. 센서가 없는 데스크톱은 화면을 끌어 각도를 흉내 내는 시연 모드
- 상품 정보: 촬영한 굿즈는 공식 상품과 아직 연결하지 않아 "등록된 구매처가 없어요" (시안의 내 에셋과 같은 문구)
- 앱 안에서 SAM 3 · 3D 복원을 바로 하지 않는다. 같은 영상으로 PC(GPU)에서 미리 만든 결과를 보여 주고, 화면 아래에 그렇게 적어 두었다
- 시안의 100원 동전 크기 기준 사진은 이 영상에 동전이 없어서 넣지 않았다

## 프로토타입 앱 실행

`lib/`에 4–25번 화면을 Flutter로 만들었다. 서버 대신 목업 API(`lib/core/network/mock_api.dart`)가 조금씩 늦게 답해서 스켈레톤 · 부분 로딩까지 볼 수 있다.

```bash
cd frontend
flutter pub get
flutter run -d chrome        # 웹으로 실행 (넓은 화면에서는 휴대폰 틀 안에 보인다)
flutter test                 # 화면 흐름 · API 테스트
```

- 웹 배포본: `main`에 합쳐지면 GitHub Actions가 `https://bloodmoon3929.github.io/goodmorning/app/`으로 올린다 (`/goodmorning/`은 관리자 페이지).
- 주소에 `?as=member`(회원) 또는 `?as=guest`(둘러보기)를 붙이면 로그인 단계를 건너뛴다. 예: `…/app/?as=member#/stores?view=map`
- 글꼴(Pretendard)과 이모지 그림(Fluent Emoji 3D)은 `assets/`에 함께 들어 있다. 라이선스는 각 폴더의 LICENSE 파일.
- `assets/brand/`: UI 시안 표지에서 자른 그림. `assets/room/`: 시안의 방 그림, `pochita/`는 팀이 직접 찍은 시험용 영상(포치타 인형)의 프레임 · SAM 3 분할 · 3D 렌더 결과
